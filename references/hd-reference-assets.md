# 参考图驱动的高清素材

在截图还原中发现内容图片像素不足，或用户要求高清素材时读取。适用于 Figma、网页和双交付。

## 生成前

- 检查素材原始像素、最终显示尺寸和裁切比例；通常按显示尺寸至少 2 倍像素准备，并按实际放大 / 导出需求提高。高清不是只改尺寸元数据或把低清截图插值拉大。
- 优先复用项目中已有清晰源图。只有截图可用时，提取完整内容图片区域作参考，排除周围文字和控件；不能把整页 UI 当成最终图片资产。
- **必须将原始素材实际传入图像生成工具的参考图参数**，并先查看该图。只写“参考截图风格”而未传图不算参考生成；不要误传上一次错误生成的图片代替原图。
- 通过项目指定 image2 通道生成；遵守可用 imagegen 技能，不因路径或分辨率便利静默切换服务。

## 还原约束

- 提示词明确“高清修复 / 忠实重绘，不重新设计”，列出人物或角色比例、姿态、视线、构图、物体位置、线条粗细、色彩和背景等不变量。
- 以原图逐项比对，避免把瘦长角色改成圆胖角色、改变手势、替换物体或增加原图没有的装饰。信息不足时说明无法恢复的细节，不把生成推测说成原始细节。
- 实现素材排除 UI 文字、按钮、状态栏、图标和标识。原插画内有文字时，按项目规则单独用真实文字 / 矢量排版；不能默默删除必要文字后声称完全还原。
- 不许绕过图像服务的限制。因真实人物等原因被拒绝时，简短说明；若采用虚构人物替代，明确其身份和与原图的差异，不声称仍是原人物。

## 保存、替换与验收

- 高清文件保存到项目 assets，使用版本化名称，保留原素材；不能只留在生成工具缓存中。
- 写入 artifacts/asset-manifest.json：原图路径、参考图路径、生成文件、像素尺寸、显示尺寸、裁切策略、实际通道、生成提示词 / provenance、对应 Figma 节点或代码调用位置、检查结果及已知差异。
- 先看生成结果，对照原图检查构图、姿态、细节和背景；不合格时只修正失败素材，不批量重复生成。
- 再替换 Figma 的对应图片填充或网页的资源引用，保留原图层尺寸、圆角、文字、控件和布局。按构图选择 FIT / FILL，检查主体是否被截断。
- 必须查看替换后的实际渲染，并在适当放大倍率下检查清晰度与裁切。上传成功不等于视觉验收；渲染检查受阻时报告具体阶段，不声称已检查完成。
- 交付时简短说明哪些图片更新、实际尺寸与主要差异。生成高清素材不会自动改变 recreate 的原图依据。
